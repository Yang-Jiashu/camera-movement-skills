# 遮挡揭示与擦除

让镜头B沿前景遮挡物的实际边界出现。先验证遮挡数据与镜头A匹配，再讨论转场的速度和风格。

## CV处理设计

用户要提前设计CV算法，或素材存在跟踪、边缘、几何、分层或时序问题时，先读 [处理方案](references/processing-pipeline.md)。参考按输入契约、预处理、算法、失败恢复与指标展开，并区分已有代码和需另行执行的设计。

如同库 [素材预处理技能](../camera-motion-prep/SKILL.md) 已安装，可按其实际帮助准备分析、稳像或mask；缺失时，本技能自己的参考也给出可执行的人工/CV处理步骤。

## 输入与掩码约定

- 需要两个视频、各自源起点、输出画幅、切换中心及过渡时长。
- 真实遮挡需要与A同一源画面、同一显示方向和同一时间段的掩码序列。检查几何裁切或稳像是否已改变像素位置。
- 掩码白色显示B、黑色保留A；灰度用于边缘羽化。检查头、中、尾状态和实际遮挡物位置。
- 掩码覆盖的不仅是物体中心，还应考虑浅色侧面、金属边、透明区域及运动模糊。

## 参数与执行

| 参数 | 语义 |
| --- | --- |
| `--mask-dir` / `--mask-pattern` | 图像序列所在目录和索引命名模式 |
| `--mask-fps` | 掩码原始采样率；工具按过渡局部时间映射，不要求等于输出fps |
| `--mask-offset` | 序列的起始索引，不是视频秒数 |
| `--feather` | 仅线性擦除的输出边宽；提供的mask保留自身灰度羽化 |
| `--cut-at` / `--transition` | 输出时间线的切换中心和过渡时长 |

例：读取从0000开始的30fps实物边界序列：

```bash
python3 scripts/apply_camera_motion.py wipe --input first.mp4 --input-b second.mp4 --output wipe.mp4 --duration 4 --cut-at 2 --transition 0.5 --mask-dir masks --mask-pattern '{index:04d}.png' --mask-fps 30 --mask-offset 0 --feather 4
```

先看 `wipe --help`。无 `--mask-dir` 时是工具提供的线性数字擦除，应命名“几何擦除”，不能写成已经跟踪了真实立柱。

## 匹配与边界

工具对输入做同一画幅的等比映射，不会自动修复错误时序或来自另一版本的mask。先校准A与mask；若需要重新跟踪，用实际边界或人工关键点生成新序列，再执行合成。

检查揭示范围随时间是否符合物体经过方向；有意遮挡回退可以存在，不要为了单调指标强行改错真实边缘。羽化不能掩盖明显错位、断边或漏掉侧面。

双视频默认无声，需要另行组织环境声或音效；不能把两场景合成报告成真实连续机位。HDR先显式转SDR，并保持mask与转换后画面的几何一致。

## 验收与交付

正常播放整个连接，重点看遮挡物进入、覆盖最多、离开三段。逐帧检查高对比边缘、薄侧面、源主体穿过边界及B的显露落点。

交付记录源文件与起点、mask来源/命名/fps/索引、输出切换时刻、羽化与画幅处理。明确是“真实遮挡跟踪合成”还是“线性数字擦除”。

## 运行入口

视频入口按CFR帧索引处理，VFR不会自动检测；精确时序或原声同步前核查帧率，必要时先规范为明确的CFR。

仓库根目录运行共享 `scripts/apply_camera_motion.py wipe`；整库安装后的本技能 `scripts/run.py` 已固定 `wipe`。两者用同一运行时，先读 `--help`；单独复制技能目录不包含共享代码。
