# 主体跟踪的CV处理设计

当前执行器是用户ROI内的纹理跟踪，未实现语义检测、身份重识别或自动遮挡后重捕获。以下将代码已有能力与需要另行执行的分析区分开。

## 1. 输入契约

- 8位SDR、已核查方向和CFR的视频；起始ROI或anchor必须对应所选起始帧。
- ROI用源画面归一化 `x,y,w,h`，包含主体的稳定纹理，减少独立背景。anchor会初始化其附近的小纹理框，不表示精确语义轮廓。
- 指定zoom、期望输出位置target、平滑时间常数、最低置信度及失跟策略。整个ROI要能放进裁切窗口。

## 2. 预处理与模型选择

1. 查看首帧、转向、遮挡和主体交叉位置，判断纹理能否代表同一对象。
2. 主体是刚性物体或稳定局部时，可先用现有稀疏光流。人体大形变时，应选稳定局部或另用语义检测、实例分割及重识别流程。
3. 检测框、分割mask、稠密光流或外部跟踪模型属于可选工具；当前命令不会自动下载或调用它们。
4. 如需先稳像，保留主体的真实运动，并把ROI坐标映射到稳像后的实际输入。

同库预处理技能存在时可按其帮助准备数据；单独安装本技能时，可用人工选框和当前跟踪器直接开始，不依赖跨技能文档。

## 3. 已有跟踪循环

1. 转灰度，在当前ROI多边形内用 `goodFeaturesToTrack` 找Shi–Tomasi角点。
2. 相邻输出采样帧之间运行金字塔Lucas–Kanade光流，再反向跟踪。
3. 按正反向状态、LK误差和前后向回环误差筛点。当前实现使用源像素尺度阈值，这些固定值不是跨分辨率质量保证。
4. 剩余点足够时，以 `estimateAffinePartial2D(..., RANSAC)` 拟合局部相似变换，并更新ROI四角。
5. 当前置信度为RANSAC内点数除以上一轮总角点数，兼顾了丢点；它不是语义身份概率，也不是仅对幸存匹配点计算的内点率。
6. 每帧在更新ROI内重新检测角点，以维持纹理点密度；未进行语义重识别。

当前代码的LK窗口、层数、像素误差阈值和RANSAC阈值可在实现中审计；CLI暴露的是最低置信度、ROI、zoom、target、平滑与fallback，不应虚构额外调参开关。

## 4. 构图生成

将ROI位置转成裁切中心，使用以秒为单位的指数平滑，系数为 `1-exp(-1/(fps*smoothing))`；0关闭平滑。再把期望target位置与ROI完整保留约束合并，构造逆仿射裁切。

几何安全优先于精确target。若背景边界clamp会把ROI挤出画面，执行器停止；不会只保留中心点便宣称整个主体完整。

## 5. 失败恢复

- 低置信、ROI越界或纹理不足：默认停止，不发布损坏结果。
- 显式hold后：保持上次裁切中心，继续播放原始视频，不冻结视频；当前实现不会自动重新捕获目标。
- hold后的后续记录可能保留初始化式置信值，应结合 `held_after_loss` 理解，不能把该数值当作重新跟踪成功。
- 多人交叉或背景劫持：人工复核身份，分段重新初始化，或换成具备语义身份约束的外部流程；仅降低置信门槛不能修复对象错误。

## 6. 验收与指标

**当前报告已有**：逐帧confidence、ROI四角、hold状态，以及全局裁切余量、clamp数量和采样放大；导出后全量解码与帧数/fps/尺寸检查。

**设计流程需另行执行**：标注少量真实主体位置，量化中心误差、框IoU、身份切换、遮挡后恢复情况、取景速度/加速度和跟随滞后。稀疏标注或高内点率不能单独证明身份一致。

以正常速度看完整段，重点复核纹理变化、遮挡、转向和交叉；任何阈值都应按主体尺度、运动速度和噪声校准。
