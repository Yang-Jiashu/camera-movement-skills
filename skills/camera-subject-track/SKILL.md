# 主体跟随重构图

先确定被跟踪的对象，再让裁切窗口跟随它。原片提供主体动作，本技能只调整二维取景，跟踪器不推断语义身份。

## CV处理设计

用户要提前设计CV算法，或素材存在跟踪、边缘、几何、分层或时序问题时，先读 [处理方案](references/processing-pipeline.md)。参考按输入契约、预处理、算法、失败恢复与指标展开，并区分已有代码和需另行执行的设计。

如同库 [素材预处理技能](../camera-motion-prep/SKILL.md) 已安装，可按其实际帮助准备分析、稳像或mask；缺失时，本技能自己的参考也给出可执行的人工/CV处理步骤。

## 输入与初始化

- 需要视频、选段、输出画幅与主体起始位置。查看实际首帧，确认选段起点与初始化帧相同。
- 优先用 `--roi x y w h` 框住主体上能稳定跟踪的部分；四值均为0–1归一化坐标。也可用 `--anchor x y` 指定稳定特征附近的点。
- 框内尽量减少独立运动的背景；不要把跟到树、墙或水纹误报成跟住了人物。
- 明确主体想维持的屏幕位置、允许的构图变化与完整肢体边界；单个中心点在画内不代表整个主体完整。

## 参数与执行

| 参数 | 决策 |
| --- | --- |
| `--zoom` | 为窗口移动预留边缘；先根据输出分辨率判断裁切余量 |
| `--target x y` | 主体希望保持的输出归一化位置；可留出行进方向的空间 |
| `--smoothing` | 以秒为单位的平滑时间常数；平衡稳定与滞后，0关闭平滑 |
| `--min-confidence` | 特征跟踪置信度下限，不等于身份识别准确率 |
| `--fallback stop\|hold` | 默认低置信时停止；用户接受后可hold窗口，主体仍按原片运动 |

例：跟随首帧中偏左的主体，ROI仅为示意，必须按实际首帧重选：

```bash
python3 scripts/apply_camera_motion.py subject-track --input input.mp4 --output tracked.mp4 --duration 4 --roi 0.25 0.2 0.3 0.5 --zoom 1.4 --target 0.45 0.5 --min-confidence 0.5 --fallback stop --smoothing 0.25
```

查看 `subject-track --help` 后设置选段、尺寸与FFmpeg。默认无声；时间映射不变且原声可用时，可用 `--audio source`。

## 失效与恢复

完全遮挡、主体离框、快速模糊、无纹理表面和相似对象交叉都可能让跟踪漂移。检查置信度和实际画面；降低阈值不能证明恢复了正确对象。

失去目标时优先缩短镜头、重新初始化下一段，或在用户接受的区间保持窗口。不要静默跟随另一对象，也不要用重复帧掩盖失跟。需要mask或人工关键点时，把补充数据与自动跟踪分开记录。

裁切中心被边界限制后，目标可能偏离指定位置；保留有效画面与主体完整性，再报告实际构图偏差。HDR先按共享工具的显式转换入口处理。

## 验收与交付

逐段正常播放，重点检查遮挡、交叉和加速位置。检查跟踪对象始终一致、主体完整、窗口无跳动，平滑没有造成明显追赶或落后。

记录初始化ROI/锚点、置信下限、平滑与失跟策略、低置信区间及边界修正。交付称“主体跟踪重构图”；它不等于在现场新增了跟拍机位。

## 运行入口

视频入口按CFR帧索引处理，VFR不会自动检测；精确时序或原声同步前核查帧率，必要时先规范为明确的CFR。

本技能依赖整库共享运行时。仓库根目录使用 `scripts/apply_camera_motion.py subject-track`；整库安装后的本技能 `scripts/run.py` 已固定子命令，接受同样参数。先读 `--help`；单独复制技能目录不包含共享代码与依赖。
