# 匹配变焦的CV处理设计

原apply执行器消费指定锚点并做裁切、混合与模糊。新增camera_pipeline match-zoom可先执行SIFT双向ratio与RANSAC配准，检查几何支持后产生锚点；它不是三维相机求解或语义识别。

## 1. 输入契约

- 两个SDR/CFR视频、各自源起点、输出画幅与整段时长。
- A/B各自的归一化视觉锚点、观察倍率、峰值倍率、切换中心及过渡时间。
- 两个锚点应在语义、形状或视觉注意力上能承接。它们可以属于不同场景，但不能因此推断真实空间相连。

## 2. 锚点准备与算法选择

1. 先人工看实际取段，标出对应对象的中心、大小和方向；不要默认取画面正中。
2. 同一建筑/平面跨时段：可另行使用SIFT或ORB匹配、比率筛选与RANSAC几何验证；有视差或动态物体时，单应性不应硬套整个场景。
3. 同类环口/门洞：可另行用轮廓、椭圆拟合或人工关键点估计中心、尺寸和朝向。
4. 不同地点的相似构图：以可解释的形状和注意力匹配为目标，不用无对应关系的全图特征或稠密光流伪造连续空间。

共享motion_match.py已实现SIFT配准；高层pipeline会保存内点图与诊断。轮廓/椭圆的语义形状匹配仍需实际工具或人工锚点。仅复制本技能时，先检查共享运行时是否已安装。

## 3. 预处理步骤

- 先统一显示方向和输出画幅，复核中心裁切后锚点是否仍在有效画面内。
- 根据两个锚点的视觉大小和方向选择峰值与切点；明显不兼容时重选片段，避免拉伸建筑来强求匹配。
- 核查HDR/SDR和亮度差异。昼夜变化可以保留，但不要把非意图过曝闪帧当作匹配成功。

## 4. 已有实现

1. A从观察倍率推向峰值，中心向anchor-a移动；B从anchor-b附近的峰值逐步退回较宽取景。
2. 过渡内在两个锚点位置分别取峰值画面，使用加权混合后叠加固定高斯模糊。
3. 每次裁切均做逆仿射覆盖检查，默认越界报错；显式clamp会改变实际中心。
4. 当前并非基于曝光时间的物理变焦模糊，也不含自动光照匹配或局部形变。

## 5. 失败恢复

- 切点注意力跳位：重新标注锚点，检查输出画幅裁切及clamp记录；必要时先用reframe准备输入。
- 透视/轮廓差异突兀：换锚点或剪辑落点；不要自动扩展成3D重建。
- 峰值像素不足：缩短高倍率停留，降低峰值或输出尺寸；把过渡的短暂放大与观察段画质分开说明。
- 长时间模糊：减少过渡，给拉出后留清楚观察段。速度应服务切换与落点，而非仅增加冲击。

## 6. 验收与指标

**当前可报告**：输入参数、几何边界余量、clamp数量、最大采样放大，以及完整解码/帧数/fps/尺寸。

**需另行检查**：切点锚点位置偏差、目标尺度差、方向差、过渡亮度变化、落点清晰度与稳定时间。人工对应点或轮廓可支持这些测量；没有实际执行不能声称“自动对齐通过”。

以正常速度判断注意力是否连续，再慢看峰值前后；阈值按对象尺寸、输出分辨率与设计强度校准。默认无声，音效和原声切换需要独立同步检查。
