# 运镜的计算机视觉处理设计

按镜头问题选算法，不把全部算法串行套用。这里覆盖常见运镜生产环节；“流程已设计”不代表“模型已安装”或“本镜头已经运行”。各技法的 `references/processing-pipeline.md` 定义自己的落点与验收。

## 导航与状态

| 环节 | 现成能力 | 条件流程，需另行执行 |
| --- | --- | --- |
| 输入和时间 | 解码、范围检查、显式HDR→SDR | 时间戳/VFR检查、镜头切分、镜头畸变标定 |
| 运动 | ROI纹理LK、背景诊断/稳像、SIFT配准、DIS/Farneback稠密流 | 局部非刚性稳像、语义重识别 |
| 图层 | GrabCut、视频mask传播、直边reveal、有限补洞和alpha合成 | 语义视频模型、matting、深度预测、大范围补全 |
| 时间/画质 | 单调时间重映射、方向模糊、编码与解码检查 | 光流插帧、去模糊、超分、时序降噪、调色匹配 |
| 空间 | 安全二维仿射与有限2.5D图层运动 | 标定、SfM/MVS、NeRF/3DGS等外部重建 |

现成能力由apply_camera_motion、prepare_motion、motion_masks、motion_layers、motion_match提供；camera_pipeline串联准备与成片。普通组合不会自动触发右列。先确认工具、模型版本、硬件、输入及输出契约，再决定是否采用。

## 1. 输入基准：先建立坐标与时间

1. 选用实际解码后的朝向和尺寸作为工作坐标，记录素材、选段、fps、颜色空间、旋转元数据和输出画幅。元数据检查不能替代查看图像。
2. 共用工具按CFR帧索引定位；VFR当前未自动检测。精确同步前用可用的时间戳探测工具核对帧间隔，必要时先规范化并保留原时间到工作时间的映射。
3. HDR先显式转换到已知SDR，保存参数。普通视觉工具拒绝已识别HDR；避免用8位未经处理的HDR解码结果作最终颜色。
4. 切点、闪光与镜头转换由观察或外部检测定位。跨切点重新初始化跟踪、mask、深度与运动轨迹，不把跨切点的匹配失败当相机猛动。
5. 代理图仅作分析；记录缩放 `s = analysis_width/source_width`。分析点坐标回到源尺寸，像素阈值同时换算。fps变化同样会改变相邻帧运动幅度。
6. 需要镜头去畸变时先标定并更新内参、坐标和有效边界；本库不会自动标定。无内参的通用畸变“修复”不得当作测量依据。

**产物**：工作媒体或引用、基准记录、镜头区间。发生任何取景/尺寸变化后，重新对齐后续ROI、锚点与mask。

## 2. 质量诊断：只修复影响任务的问题

1. 抽看起点、中段、终点和动作最快处；必要时计算灰度梯度、过曝比例、噪声或压缩指标作为筛查。Laplacian清晰度分数受纹理影响，不能直接跨场景给统一及格线；这些画质指标不是现成CLI的自动验收。
2. 低照度导致特征不稳定时，可在分析分支轻度降噪/局部对比增强；保留源彩色画面用于合成，不把处理后的噪点当新纹理。
3. 原片运动模糊、遮挡和低分辨率已经丢失信息。优先缩小动作幅度、缩短镜头或换素材；外部去模糊/超分可改变内容，需检查文字、人脸和细结构。
4. 固定整段参数或做时序约束，避免逐帧自动调色、降噪或超分带来呼吸与闪烁。未执行的增强只写为建议。

**产物**：可用区间、失败原因、是否需要外部增强；不以“4K导出”冒称恢复了细节。

## 3. 特征、匹配与运动模型

### 连续视频：当前LK路线

1. 用户指定主体时在主体ROI找角点；稳像时在稳定背景ROI找角点。二者不能混用同一对象语义。
2. Shi–Tomasi角点 → 金字塔LK前向跟踪 → LK反向返回 → 前后向误差与状态筛选 → RANSAC相似变换。
3. 统计匹配保留率、内点数/比例、重投影残差及空间分布。特征只集中在一小角，或匹配全在移动汽车上，即使残差小也不说明全局相机运动可信。
4. 当前主体跟踪的confidence是通过筛选与RANSAC的几何支持量，不是语义概率。遮挡后不能靠它确认“还是同一个人”。

### 跨图/跨时段：SIFT路线已实现

1. 同一刚性结构可用SIFT/ORB描述子匹配，按描述子选择距离度量，做双向/ratio筛选和RANSAC几何验证。
2. 优先使用最简单足够的模型：平移→相似变换→仿射；近似同一平面或纯旋转的图像可试homography。
3. 单应性不能统一解释存在强视差的非平面场景；昼夜、瀑布、反射与重复窗格需要人工对应点或局部锚点，失败时退回手动匹配。
4. 比较模型残差与空间分布，检查映射四角、尺度、行列式/翻折；复杂模型更贴合少量错误点不等于更正确。

**产物**：带坐标系的对应点/变换、模型类型、内点掩码、置信与人工复核结果。motion_match.py输出自动锚点与配准报告，camera_pipeline match-zoom会调用它；失败可明确指定人工锚点。

## 4. 背景稳像与主体跟随分开设计

1. `prepare_motion.py analyze`先评估背景模型；`stabilize`平滑相似变换轨迹。`subject-track`让取景跟随ROI，两者目的不同。
2. 稳像强度按镜头意图设置；只去掉需要消除的高频抖动。把持续行进全部锁死会使构图和速度感变差。
3. 统一规划稳像、画幅转换、数字推近与roll的总裁切预算。现成准备工具和效果工具为独立渲染阶段，不能声称已合并成一次采样。
4. 低可信帧默认停止；显式hold区间必须在报告和视觉检查中保留。完全遮挡不能用插值承诺恢复身份；重新出现时手工确认并分段重启。
5. 通过对比背景短周期残差、主体构图误差与裁切损失评估效果。稳像报告中的 `predicted_model_residual_after` 来自拟合变换和平滑目标，不是编码后重新跟踪的实测改善；要报告实际收益，另行重跟踪输出并保持可比较背景与单位。现成几何指标不能代替整段播放。

**产物**：工作片、运动报告、稳像裁切值、低可信区间；后续取景在新尺寸重新初始化。

## 5. 分割、mask与alpha

1. **静态硬轮廓**：现成GrabCut使用矩形与种子，适合颜色可分、边界较明确的单帧前景。修补误分孔洞时避免抹去真实镂空。
2. **视频目标**：SAM 2等外部分割器需逐镜头初始化、传播并在遮挡/重现位置补正。保留对象ID，防止多人交叉后换目标；本库未内置此适配器。
3. **发丝/透明/运动模糊边**：语义mask不是matte。使用人工trimap或适当matting方法，并检查alpha与颜色去污染；不靠大羽化半径掩盖错边。
4. **空间滤波**：形态学开闭、连通域清理或边缘引导滤波只能按局部问题使用；细枝、栏杆、手指不能因“小区域”而全部删除。motion_layers提供显式可配置连通域/孔洞清理，默认保留真实结构；单帧mask入口不默认套用这些操作。
5. **时序一致**：对齐后检查面积、重心、边界位移和跳变；可用光流传播辅助，遮挡区重新标注。运动快时面积可正常变化，不设置脱离场景的统一跳变阈值。
6. 输出消费端所需语义：图层alpha白=前景；擦除mask白=镜头B。尺寸、起始帧、fps、编号、方向、羽化单位均写入资产说明。

**产物**：静态alpha或逐帧序列、黑白语义、来源/人工修订与时间坐标；原始float或高位深母版按需要另存，8位PNG是当前CLI消费格式。

## 6. 深度与2.5D分层

1. 明确需求是前后层次、相对距离还是米制几何。普通相对深度不能通过保存16位图就变成米制深度。
2. 可选单目深度模型如Depth Anything V2，记录模型/权重、输入缩放、输出近远方向、单位和有效区域；模型输出与用户标注冲突时复核。
3. 相对深度用于辅助分层与运动幅度，不直接等于干净alpha。深度边缘应与主体轮廓核对，薄物体、玻璃、天空与反射列入人工检查。
4. 视频深度保持时间尺度一致；独立每帧min/max归一化可能产生呼吸。外部光流对齐或视频深度方法需保留遮挡无效区，不能盲目跨边缘平滑。
5. 准备前景色、alpha、完整背景；按预定最大位移和缩放范围检查暴露区。深度图不会自动补出隐藏背景。
6. 当前parallax/vertigo命令只消费显式图层，不读取深度文件，也不自动生成多层mesh。需要新深度渲染器时另行实现并验证。

**产物**：深度母版及约定（若使用）、有序图层、已补全区域、允许运动范围；称为有限2.5D演绎。

## 7. 光流与时间重映射

1. 当前LK是稀疏运动追踪；当前speed-ramp是积分速度权重后取源帧，二者都没有实现光流插帧。
2. motion_masks内置DIS/Farneback稠密流，RAFT仍需外部模型；输出明确 `frame t → t+1` 的源像素位移，保存缩放与有效性；处理反方向时重新估计或可靠求逆。
3. 用前后向一致性、光度残差和边界/遮挡检查判断流是否可用。反射、流水、闪光和大遮挡的低残差也不一定代表物体对应正确。
4. 需要慢于可用原帧时，优先真实高帧率输入；外部插帧要处理双向warp、遮挡和融合，并检查重影/扭曲。RAFT给光流，不是完整插帧器。
5. 速度映射保持单调，记录每个输出时刻对应源时刻。重复源帧只能明确许可；重复帧、交叉溶解或方向模糊不能标作真实慢动作。
6. 变速后重新设计声音；不能把原音轨直接复制到新时间线上假称同步。

**产物**：时间映射、可用源帧覆盖与重复记录；若使用外部插帧，另存算法/遮挡策略和人工审查结果。

## 8. 补洞、三维与新视角

1. motion_layers为有限运动内置Telea/NS补洞，并核查整个运动的暴露区与填充深度；大运动优先从无遮挡参考取真实背景。
2. 使用外部修复/生成时保存被修改区域、参考帧与方法，逐帧检查纹理和曝光一致性。生成内容不当作拍摄中存在的事实。
3. 真正机位环绕需要多视角覆盖与相机/场景几何。SfM恢复位姿与稀疏结构，MVS可进一步重建；重建质量取决于视角、纹理、重叠与动态物体。
4. NeRF/3DGS等另需适当数据与训练/渲染流程，不能默认单张照片就有可靠背面。纯旋转、同一点数字缩放或重叠不足的素材可能缺乏可恢复视差。
5. 标定与位姿输出包含内参、畸变、坐标系、尺度来源和有效视角范围；没有物理尺度时明确尺度不确定。

**产物**：可用覆盖范围、重建资产/外部工具版本或明确的生成标记。本库不内置三维重建/新视角引擎。

## 9. 合成、色彩与最终验收

1. 合成前确认颜色、alpha预乘约定、尺寸与时序；高反差边缘必要时用线性光合成，再转显示空间。当前通用合成为8位SDR显示编码值混合，不能称为线性光/HDR制作管线。
2. 匹配两镜头亮度/白平衡时保护高光、肤色与文字；有意昼夜切换可保留差异。大范围闪白可能是切换节奏问题，不一定需要自动调色。
3. 自动检查几何有效域、mask帧覆盖、时间单调、输出尺寸/fps/帧数与完整解码。全黑检测、边缘空洞和音频峰值视任务补做，不能仅从解码成功推断。
4. 技法指标：roll方向/总角度/回正，track对象与完整性，match-zoom锚点偏差，wipe边缘时序，vertigo前景尺度，speed-ramp落点及重复源帧。
5. 关键帧用于定位缺陷；正常速度看整片并检查声音、切点和高风险区间。记录“已执行”“人工确认”“尚待执行”，不把设计阈值填成实测值。

**产物**：最终视频、算法与资产来源报告、实际检查结果及局限。量化阈值在具体镜头设定；以像素或画面对角线归一化表达，并写清测量方法与容忍度。

## 10. 可选资产交接记录

下列为**设计交接字段**，不是现有CLI可直接导入的配置文件。CLI实际参数以 `--help` 为准；JSON输出字段以具体工具报告为准。

```json
{
  "source": "clip.mp4",
  "working_media": "clip-sdr-cfr.mp4",
  "frame_basis": {"width": 1920, "height": 1080, "fps": 30, "start_seconds": 2.0},
  "coordinate_space": "display-oriented working source, normalized 0..1",
  "asset": {"kind": "wipe-mask-sequence", "pattern": "masks/{index:04d}.png", "first_index": 0,
            "start_seconds": 1.8, "fps": 30, "white_means": "reveal-input-B"},
  "method": {"name": "manual-or-external-model", "version": "record-actual-version", "checkpoint": null},
  "review": {"status": "pending", "invalid_intervals": [], "manual_corrections": []}
}
```

若用flow另记方向与像素单位，若用depth另记relative/metric、近远方向和无效值，若用matte另记alpha数值/位深、是否预乘及RGB色彩空间。缺字段先补说明，不靠文件名猜测。

## 一手资料

- [OpenCV光流与跟踪API](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html)：稀疏LK、Farnebäck、运动模型。
- [OpenCV几何估计API](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)：相似/仿射估计、标定和投影。
- [OpenCV特征匹配与单应性](https://docs.opencv.org/4.x/d1/de0/tutorial_py_feature_homography.html)：描述子、RANSAC与平面映射。
- [OpenCV GrabCut](https://docs.opencv.org/4.x/d8/d83/tutorial_py_grabcut.html)：矩形与人工种子条件。
- [SAM 2官方仓库](https://github.com/facebookresearch/sam2)：外部视频分割方案。
- [Depth Anything V2官方仓库](https://github.com/DepthAnything/Depth-Anything-V2)：相对深度与独立的metric模型路线。
- [RAFT官方仓库](https://github.com/princeton-vl/RAFT)：外部光流估计方案。
- [COLMAP教程](https://colmap.github.io/tutorial.html)：多视图SfM/MVS的外部重建流程。

以上用于算法选择与接口设计；不声明它们是最新模型排行，也不表示已经安装、封装或在本库素材上验证。
