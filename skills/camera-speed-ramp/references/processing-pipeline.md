# 速度渐变的CV与时间映射设计

当前命令做CFR帧索引的单调选择，不生成光流中间帧、不识别动作，也不自动匹配音乐节拍。动作分析与音频处理属于需要另行执行的设计流程。

## 1. 输入契约

- 可读SDR视频、真实源fps、CFR选段起点和源时长，以及目标fps和输出时长。
- 确认输入是原始高帧率视频还是已经慢放的缓存；缓存标为30fps并不表示它具有新的120fps采样能力。
- 速度点从归一化输出时间0到1递增，速度权重为正；当前命令不包含倒放、停格、反复回放或非单调源时间映射。

## 2. 分析与预处理设计

1. 标出关键事件：车头经过、人物落地、转身、遮挡进入等；先确定哪里必须看清。
2. 可用稀疏背景光流和主体框轨迹估计运动量，或对有标注动作做事件检测；全画面差分可能被水、灯光、噪声和曝光变化主导。
3. 用源时间轴标记动作，再设计输出时间轴的快慢分配；不要只按“流量大=应减速”自动决策。
4. 若需卡节拍，另行检测音频起音/节拍并人工复核。现有命令不含beat tracking，也不生成同步音乐。

同库预处理工具可帮助盘点，但缺失时人工时间标记已可完成这份设计；稠密光流或动作模型是可选外部工具。

## 3. 已有映射算法

1. 对速度点做线性插值，得到每个输出采样位置上的正权重。
2. 用梯形累计积分建立单调源位置，并整体归一化到所选可用源时长。
3. 把源位置乘源fps后向下取整到真实源帧索引；因此权重4不一定等于实际4倍速。
4. 检查相邻索引是否重复。默认拒绝重复；显式 `--allow-repeat` 才允许重复真实帧，始终不做插帧。
5. 报告实际速度范围、源帧索引、重复数量和跨过的源帧数；快速段会丢弃部分采样。

源选段末尾会为最后一个有效源帧保留空间；不要把半开区间末端或容器时长直接当作可读取的新帧。

## 4. 质量设计

- 慢段需要的真实帧密度高于输入时，优先使用原始高fps片、调整曲线/时长或降低输出fps。
- 如用户选择光流插帧，应另用实际插帧工具，验证遮挡、薄边和重复结构，并报告合成帧；不能用本命令宣称完成。
- 直接保留未映射的原声会失去同步。本变速命令不接受源原声复制，需要单独进行同映射音频伸缩或配乐。

## 5. 失败恢复

- 重复帧报错：检查输出慢段是否过长，而不是直接许可重复并称之为流畅慢动作。
- 关键动作跳过：给事件更多输出时长，降低该段速度权重，或缩短两端无关素材。
- 快慢突然刺眼：平衡关键点间权重变化，检查实际速度曲线与切点；重复锐化或光流不能修复错误节奏。
- VFR同步不可靠：先按真实时间戳规范到明确CFR，再重新标定动作位置。

## 6. 验收与指标

**当前报告已有**：完整源帧索引序列、重复/丢弃数量、实际速度范围、无插帧声明及输出解码/帧数/fps/尺寸。

**需另行计算**：速度/加速度曲线、关键事件在输出的位置、慢段姿态可读性、快段方向感，以及单独音频处理后的同步偏差。光流统计只能提供辅助证据，不能替代动作语义检查。

正常速度观看完整段，再复核关键事件与速度变化处；允许的加速度、重复量和音画偏差应按交付目的设定，不把示例数值当作通用保证。
