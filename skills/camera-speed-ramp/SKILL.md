# 速度渐变

通过时间重映射改变真实运动的节奏，保留原片动作方向与顺序。速度渐变属于时间处理，可与运镜配合，本身不产生新视角。

## CV处理设计

用户要提前设计CV算法，或素材存在跟踪、边缘、几何、分层或时序问题时，先读 [处理方案](references/processing-pipeline.md)。参考按输入契约、预处理、算法、失败恢复与指标展开，并区分已有代码和需另行执行的设计。

如同库 [素材预处理技能](../camera-motion-prep/SKILL.md) 已安装，可按其实际帮助准备分析、稳像或mask；缺失时，本技能自己的参考也给出可执行的人工/CV处理步骤。

## 输入与节奏设计

- 读取输入的帧率、时长与已有时间处理；确认是高帧率原片，还是已经被变速的30fps缓存。
- 需要选段起点、源选段时长、输出时长与关键动作时刻。先把“该在哪里看清什么”标出来。
- 在动作发生前后安排快慢变化；不为卡音乐节拍任意越过关键动作或破坏屏幕方向。
- 明确是否需要同步声音。变速后的画面与直接复制的原声通常不再同步。

## 参数与执行

| 参数 | 语义 |
| --- | --- |
| `--source-duration` | 要使用的原片选段长度，从 `--start` 开始 |
| `--duration` | 整段输出时长 |
| `--speed-points` | `归一化输出时间:相对速度权重` 序列，不是保证的绝对倍速 |
| `--allow-repeat` | 明确允许重复源帧；默认拒绝需要重复帧的映射，不会自动插帧 |

例：把8秒源动作组织为4秒，两端较慢、中间较快：

```bash
python3 scripts/apply_camera_motion.py speed-ramp --input input.mp4 --output ramp.mp4 --start 0 --source-duration 8 --duration 4 --speed-points '0:1,0.5:4,1:1'
```

查看 `speed-ramp --help` 后确定尺寸和输出fps。工具会把权重整体归一化到源时长/输出时长，实际速度以报告为准；不要直接将示例的权重4称为实际4倍速。

## 帧选择与边界

源时间映射保持单调。检查实际选择的源帧、跨帧幅度和重复情况，尤其是慢段及曲线端点。

输出fps高于慢段可用真实帧密度时，优先使用原始高帧率素材、减轻减速或调整输出。用户接受重复帧时才加对应许可，并准确说明；此工具不会把重复或合成帧报告成真实采样帧。

工具的变速命令默认无声，并不接受直接复制源音频来制造假同步。需要音频时，用一致时间映射另行处理或配乐，检查音高、切点和响度。HDR需先显式转SDR。

## 验收与交付

正常播放完整段，检查慢段是否顺滑、快段是否仍有方向和动作信息，速度变化是否贴合关键时刻。再检查映射单调、实际速度曲线、重复帧与选段尾端。

交付记录源起点/时长、输出时长/fps、相对权重和实际速度范围；说明是否丢帧、重复、插值及如何处理声音。不把单纯加速称为移动延时拍摄，也不把速度渐变称为新机位。

## 运行入口

视频入口按CFR帧索引处理，VFR不会自动检测；精确时序或原声同步前核查帧率，必要时先规范为明确的CFR。

仓库根目录运行 `scripts/apply_camera_motion.py speed-ramp`；整库安装后本技能 `scripts/run.py` 已固定子命令。先读 `--help`；仅复制技能目录不包含共享运行时和依赖。
