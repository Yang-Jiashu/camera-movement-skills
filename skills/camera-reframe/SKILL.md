# 数字重构图

把取景窗口从明确起点移动到明确终点，让细节、主体或环境按顺序进入注意力。支持用户自有的8位SDR照片与视频。

## CV处理设计

用户要提前设计CV算法，或素材存在跟踪、边缘、几何、分层或时序问题时，先读 [处理方案](references/processing-pipeline.md)。参考按输入契约、预处理、算法、失败恢复与指标展开，并区分已有代码和需另行执行的设计。

如同库 [素材预处理技能](../camera-motion-prep/SKILL.md) 已安装，可按其实际帮助准备分析、稳像或mask；缺失时，本技能自己的参考也给出可执行的人工/CV处理步骤。

## 输入与取景判断

- 明确输入文件、视频起点、输出时长、画幅与分辨率；照片的时长是设计值。
- 查看起、中、末画面与完整运动，确认原片已有的相机和主体运动；优先保留能实现目的的原始运动。
- 找出主体完整边界、建筑顶部、地平线与字幕区域，再确定起止缩放和窗口中心。
- 若用户要真实横移视差、抬高机位或绕到背面，先判断原片是否已记录；本技能的二维裁切不会增加这些信息。

## 参数与执行

| 参数 | 决策 |
| --- | --- |
| `--zoom-start` / `--zoom-end` | 相对最大同画幅裁切的倍率；增大为数字推近，减小为数字拉远 |
| `--center-start x y` / `--center-end x y` | 校正显示方向后的源画面归一化中心，范围0–1 |
| `--easing smooth\|linear` | 推拉揭示可平滑起停；连续行进匹配相邻镜头时可选匀速 |
| `--bounds error\|clamp` | 默认遇到越界停止；clamp会改变请求路径，需要检查并记录修正 |

例：让画面从宽景缓慢收向偏右主体，文件名替换为实际素材：

```bash
python3 scripts/apply_camera_motion.py reframe --input input.mp4 --output reframe.mp4 --duration 4 --zoom-start 1.05 --zoom-end 1.3 --center-start 0.5 0.5 --center-end 0.6 0.5 --easing smooth
```

先读取本机 `reframe --help`，据素材补充 `--start`、输出尺寸和 `--ffmpeg`。需要保留同步原声时可用 `--audio source`；默认导出无声，并在交付中说明。

## 几何与画质

设有效源尺寸为 `Ws×Hs`、输出为 `Wo×Ho`、`r=Wo/Ho`，最大同画幅窗口为 `Bw=min(Ws,Hs*r)`、`Bh=Bw/r`。不放大采样时，倍率上限为 `min(Bw/Wo,Bh/Ho)`；稳像、旋转及畸变校正消耗的边缘需先扣除。

窗口右移时，画面内容向左运动。分别写清“窗口方向”和观众看到的方向，不把数字横移标成实拍truck或pan。

HDR素材先使用共享工具的 `convert-hdr --help` 明确转换到SDR；不要对已转换素材重复tone mapping。源图分辨率不足时，缩小幅度、降低输出尺寸或如实说明放大采样。

## 验收与交付

正常速度看完整镜头与切点；检查主体完整、边界有效、途中无突停及意外反向。首末帧正确不能证明路径中间安全。记录起止构图、倍率、中心、节奏，以及程序报告的裁切修正和采样放大。

交付称“数字推近/拉远/横纵重构图”；同时保留原片里的真实运动。用户只要方案时，给出镜头规格和实现条件即可。

## 运行入口

视频入口按CFR帧索引处理，VFR不会自动检测；精确时序或原声同步前核查帧率，必要时先规范为明确的CFR。

本技能属于整库，共用FFmpeg及Python运行时。仓库中从项目根目录运行上述命令；整库安装后可用本技能的 `scripts/run.py`，它已固定 `reframe` 子命令。先运行该入口的 `--help`，其余参数相同；只复制本技能目录不会自动带上共享运行时。
