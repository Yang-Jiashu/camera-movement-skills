# 重构图的CV处理设计

这份流程可独立阅读。标为“已有代码”的步骤在共享 `apply_camera_motion.py` / `motion_core.py` 中；分析、稳像、显著性或自动构图属于另行执行的预处理设计，不能假定每次导出已自动完成。

## 1. 输入契约

- 输入是可读8位SDR图像或视频，显示方向和像素宽高比已核查；透明前景转入显式分层流程。
- 视频需要选段起点、持续时长和CFR时间轴。当前效果入口使用帧索引，不自动识别VFR。
- 输出契约包含画幅、分辨率、fps、缩放与中心的起止值，以及主体不能被切掉的边界。

## 2. 预处理设计

1. 解码代表帧与完整运动片段，分别识别机位运动、主体运动及光学变焦。
2. 如果手抖影响取景，先用背景静态区域估计相机运动；动人、流水、近景遮挡不应主导全局拟合。
3. 可用稀疏角点光流加鲁棒相似变换，平滑运动轨迹以去除高频抖动；先保留有意pan，再计算稳像后的有效像素支持区。
4. 需要自动主体位置时，可用人工框、已验证的检测/分割结果或特征轨迹。当前reframe命令不内置语义主体检测。

若安装了同库 `camera-motion-prep`，可查看其分析或稳像入口的实际帮助；缺失时按上述流程用可用CV工具或人工关键点完成，不假称预处理已运行。

## 3. 已有代码与算法选择

`Reader`按时间选择真实解码帧；图像在设计时长内保持同一输入。`crop_matrix`生成输出到源图的逆仿射映射；`Camera.draw`用 `warpAffine` 的逆映射和三次插值采样。

该命令以显式参数产生窗口轨迹，不使用稠密光流、深度估计、自动稳像或自动构图。`smooth`为标量smoothstep插值，`linear`为匀速插值；它们不是从画面估计的相机轨迹。

## 4. 几何计算步骤

1. 按源尺寸和输出画幅计算基础采样步长 `step=min(Ws/Wo,Hs/Ho)/zoom`。
2. 用归一化中心映射到源像素坐标，构造逆仿射矩阵；所有变换合并后只采样一次，减少连续重采样。
3. 将输出四角逆映射到源图，验证全程有效支持。矩形、无额外非线性变换时四角足够；若叠加畸变校正、拼接或非矩形稳像有效区，还要检查整个采样足迹。
4. 默认越界报错；显式clamp会改变实际中心，并在报告中统计。不能把修正后的路径描述为完全执行了原请求。
5. `output_pixels_per_source_pixel>1`表示放大采样，检查报告中的最大值，并按画质目标设置 `--max-upscale`。

## 5. 失败恢复

- 主体被裁断：改中心、减小zoom或修改输出画幅；若主体移动，考虑主体跟踪，不让单一直线窗口假装智能跟随。
- 窗口安全但稳像后边缘露空：重算组合变换的有效区，不继续沿用原图矩形余量。
- 插值后细线抖动：减小运动速度/幅度、提高中间采样分辨率，检查是否多次有损缩放；强锐化不是几何修复。
- HDR被拒绝：显式转换一次再执行；不要去掉HDR标签把数据冒充SDR。

## 6. 验收与指标

**当前代码可提供**：全量解码、输出帧数/尺寸/fps、最小源边界余量、clamp样本数量、最大采样放大。

**需另行测量或观看**：主体完整率与留边、窗口速度/加速度、原片自然运动是否被反向抵消、视觉细线闪烁。可计算主体框变换后的归一化边界，以及轨迹的一阶/二阶差分；这些数值没有通用合格阈值，应按主体速度、输出分辨率和镜头目的校准。

正常播放整段与前后切点，再针对边缘最紧和加减速变化处复核。解码通过只证明文件与时间线可读，不能替代构图和运动质量检查。
