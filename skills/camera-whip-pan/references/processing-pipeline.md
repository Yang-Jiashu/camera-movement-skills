# 甩镜转场的CV处理设计

现有命令使用确定性平移拼接和方向均值模糊，不自动估计真实相机轨迹，也不做跨场景光流形变。下面的运动分析与镜头选择是需要实际执行的设计流程。

## 1. 输入契约

- 两个SDR视频、各自源起点、CFR时间线、输出画幅，以及整段时长、切换中心和过渡时长。
- A至少覆盖到过渡末尾；B至少覆盖从过渡开始到整段结束所需的时长。根据工具实际时间映射检查源长度。
- `direction`表示B从哪一边进入；例如right使B从右侧进入，画面内容整体向左滑动。不要把这个枚举直接称作相机向右移动。

## 2. 预处理与镜头匹配

1. 观察A/B的主体、景别、地平线、已有运动方向和清楚落点。
2. 如需量化方向，在静态背景区跟踪角点，使用LK加RANSAC相似变换或稳健流场统计；排除车、人、水和大面积遮挡。
3. 镜头内部稳定后，比较局部亮度/颜色和视线关系；按需做固定色彩匹配，不让逐帧自动调整造成闪烁。
4. 两输入会被中心等比裁成同一输出画幅。关键主体偏心时，先独立重构图，不能假定甩镜命令会识别并保留它。

可选的稠密光流能帮助判断运动分布，但不是当前命令的内置依赖；不同场景之间的光流通常没有可靠物理对应。预处理技能缺失时，上述人工选片与稀疏估计已可作为执行方案。

## 3. 已有合成步骤

1. 对A、B分别做同一输出尺寸的安全等比采样。
2. 过渡前显示A，过渡后显示B；过渡内按 `smooth` 或 `linear` 计算位移进度。
3. 根据方向横向或纵向拼接两幅图，再移动输出窗口。拼接覆盖整个窗口，不依赖黑色画布填空。
4. `cv2.blur`沿运动轴使用均值核；核宽随 `sin(pi*u)` 增减，始末模糊小、中段最大。`--blur`控制峰值输出像素宽度。
5. 切换后恢复正常采样，提供清楚落点。没有自动生成新的空间、没有真实镜头的长曝光测量。

## 4. 参数设计

- 转场时间和模糊核按输出分辨率、位移速度与节拍校准；建议先用中等幅度短预览，不把示例帧数和核宽当作通用标准。
- 对比“B进入边缘”和观众看到的内容方向；源相机方向、主体方向和数字滑动方向需要分别记录。
- 要做真实摄影甩镜时，规划实际机位摇动和对应落点；数字拼接不应冒称原片捕捉了同一连续摇动。

## 5. 失败恢复

- 方向反跳：重选源区间或改变数字方向；不随意镜像含文字和地标的画面。
- 中间清楚看到两地硬缝：缩短过渡、调整峰值模糊与切点，或采用更相容的落点；延长模糊不一定能修复语义冲突。
- 全程糊：减少核宽、缩短模糊区间，核查落点观察段。
- 高对比帧闪或人物切半：调切点和取景，不把光流形变当作保证自然连接的修复。

## 6. 验收与指标

**当前程序验证**：输入时长范围、采样几何、输出全量解码、尺寸/fps/帧数；不自动评分转场美感。

**需另行测量**：静态区域流向一致性、转场中亮度变化、边缘空白、接缝可见时长、落点锐度与落点稳定时间。流场方向应在合适背景区统计，运动主体不能直接代表相机方向。

正常速度观察动作和节拍，再慢看起甩、中段接缝和落点。默认无声，音效、原声淡变与音乐属于单独的声音设计及同步检查。
