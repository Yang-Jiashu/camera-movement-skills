# 甩镜转场

用快速位移和方向性模糊把注意力从镜头A带到镜头B，再落到可读构图。数字转场是后期组织，不证明两场景被连续拍摄。

## 输入与匹配

- 输入两个视频，分别确定起点、输出画幅、整段时长与切换中心。
- 看A的退出方向和B的进入方向；优先借用原片已有运动，避免相反方向突然拉扯。
- 明确切换前后观众应该看什么。没有清楚落点时，先重选片段或调整取景。
- 高对比边缘、字幕和近景人物容易暴露接缝；不要为了方向匹配而随意镜像地标、文字或人物动作。

## 参数与执行

| 参数 | 语义 |
| --- | --- |
| `--input` / `--input-b` | 镜头A与B，分别用 `--start` / `--start-b` 定位源选段 |
| `--duration` | 包含两侧观察段和转场的整段输出时长 |
| `--cut-at` | 切换中心在输出时间线上的秒数 |
| `--transition` | 甩动覆盖的时间，应给稳定落点留空间 |
| `--direction right\|left\|up\|down` | 方向枚举以工具定义为准，先预览确认观众看到的运动方向 |

例：在4秒示例中，用半秒横向甩动连接两个场景：

```bash
python3 scripts/apply_camera_motion.py whip --input first.mp4 --input-b second.mp4 --output whip.mp4 --duration 4 --cut-at 2 --transition 0.5 --direction right
```

从 `whip --help` 确认取段、尺寸与FFmpeg参数。两段会按输出画幅中心等比裁切；若关键主体偏心，先用重构图流程准备合适输入。

## 节奏与失败边界

模糊集中在快速运动和切点附近，退出后恢复清晰。转场时长根据幅度、画幅和节奏选择，不把一个固定帧数套给所有素材。

检查拼接覆盖整个输出区域；不能用黑条或空白填充甩动中间。颜色、亮度或视线差异过大时，短模糊不能自动修复空间关系，换片段通常比延长模糊更有效。

共享工具默认无声，双视频不提供假同步的原声拼接。需要声音时，另行设计原声淡变、风切或节拍，并验证与实际甩动同步。HDR素材先显式转SDR。

## 验收与交付

以正常速度看完整A→B段，再慢看起甩、最模糊点与落点。检查方向连续、接缝被覆盖、途中无黑边、落点及时清楚，人物和文字没有意外倒置。

交付记录两段源选区、输出切换中心、方向、时长、画幅裁切及声音处理。准确称“数字甩镜转场”；只有原片实际包含的摇动才称实拍whip pan。

## 运行入口

视频入口按CFR帧索引处理，VFR不会自动检测；精确时序或原声同步前核查帧率，必要时先规范为明确的CFR。

本技能依赖整库共享运行时。仓库根目录用 `scripts/apply_camera_motion.py whip`；安装后的本技能 `scripts/run.py` 已固定子命令。先读 `--help`；仅复制技能目录不会包含共享工具。
